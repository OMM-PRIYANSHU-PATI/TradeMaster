# Phase 5 Scope: Performance Analytics & Metrics

## 1. Phase Objective
Phase 5 is responsible for implementing **Module M (Analytics)**. It consumes the raw trade execution logs, P&L primitive outputs, and simulated portfolio histories generated by Phase 3/4 Backtests (or Phase 2 Paper Trading) to compute deterministic, risk-adjusted performance statistics (e.g., Sharpe, Maximum Drawdown, Profit Factor, Win Rate, Expectancy).

## 2. Existing Dependencies
Phase 5 is entirely downstream of the trading and execution core. It depends directly on:
* **Module A (Authentication / Account)**: To resolve ownership of portfolios/backtests.
* **Module E (Paper Trading Foundation)**: Reusing `PnlService` and `TradeRecord` for raw execution data.
* **Module E (Backtesting & Strategies)**: Reusing `HistoricalDataProvider` and `BacktestEngine` output data (equity curves and trade logs).

## 3. In-Scope Features
Explicitly derived from `trademaster-features/features_md`:
* `100-return-pandl-drawdown-volatility.md` (Peak-to-trough drawdown calculation, annualized return, volatility of equity curve)
* `101-sharpe-like-risk-adjusted-metrics.md` (Sharpe, Sortino ratios based on periodic returns vs risk-free rate)
* `102-win-rate-profit-factor-average-win-loss-expectancy-risk-reward.md` (Calculations based directly on `TradeRecord` aggregates)
* `103-exposure-concentration-turnover-strategy-contribution.md`
* `104-consistency-maximum-drawdown-recovery-period.md`
* `105-risk-adjusted-performance-trade-frequency-strategy-stability.md`
* `106-performance-by-market-timeframe-strategy.md`

## 4. Out-of-Scope Features
The following are **strictly excluded** from Phase 5:
* Live brokerage execution / real-money trading
* Autonomous or automated live trading
* Copy trading / Social trading (Modules K, I, J, O, G, H)
* AI recommendations or Coaching (Module N)
* Options, futures, margin, and leverage (Restricted to spot trading primitives)
* Payment systems / Subscriptions (Module R)
* Modifying the existing Phase 4 Strategy DSL or Phase 2 Execution engines

## 5. Architecture
Phase 5 introduces a new stateless Analytics Domain.

```text
Existing Phase 0-4 Foundation (Auth, User)
            ↓
        Phase 5
 (Analytics Service, Metric Aggregation, Math Utilities)
            ↓
Existing Paper/Backtest/Trading Infrastructure
(TradeRecords, Equity Curves, PnlService)
```

**Reusable Services:**
* NO duplicate execution engine will be created.
* NO duplicate fee/P&L calculations will be created (Phase 2 `PnlService` handles raw realized/unrealized base math).
* NO duplicate position tracking.

## 6. Database Changes
* **New Table**: `PerformanceMetric` or `AnalyticsSnapshot`
  * Links to `BacktestResult` or `PaperAccount`.
  * Stores pre-calculated aggregates (e.g., `winRate`, `profitFactor`, `maxDrawdown`, `sharpeRatio`).

## 7. API Changes
* `GET /analytics/backtest/:id` - Retrieves computed metrics for a backtest.
* `GET /analytics/portfolio/:id` - Retrieves computed metrics for a live paper portfolio.

## 8. Frontend Changes
* `/analytics` route.
* Visual components for displaying equity curves (using existing data arrays).
* KPI grids for Profit Factor, Win Rate, Maximum Drawdown, Sharpe.

## 9. Security Requirements
* **Authentication**: All endpoints require active session.
* **Authorization / IDOR**: Users can only request analytics for portfolios/backtests they explicitly own (enforced via standard Phase 1 ownership checks).
* **Validation**: Request parameters (timeframes, metric selections) strictly validated via DTOs.

## 10. Testing Requirements
* **Unit Testing**: Mathematical purity. The formulas for Sharpe, Sortino, and Drawdown must have deterministic unit tests against known, hardcoded equity curves.
* **Integration Testing**: Full pipeline from `BacktestEngine` generation to `AnalyticsService` ingestion and persistence.
* **Regression**: Must not break Phase 1, Phase 2, Phase 3, or Phase 4 existing suites.

## 11. Acceptance Criteria
* [ ] Analytics engine correctly computes `Win Rate` and `Profit Factor` from a known Phase 4 strategy output.
* [ ] Analytics engine correctly computes `Max Drawdown` and `Sharpe Ratio` from an equity curve.
* [ ] All calculations use `Prisma.Decimal` (or a standardized high-precision float approach) to prevent rounding drift.
* [ ] Attempting to access another user's analytics via API returns `403 Forbidden` or `404 Not Found`.
* [ ] NO duplicate trading engines are implemented.
